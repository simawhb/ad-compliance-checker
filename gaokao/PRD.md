# 驷马报考 — 产品需求文档 (PRD)

> 版本：v1.0 | 2026-06-30
> 目标用户：C端考生和家长（移动端优先）
> 核心差异化：录取数据 + 论坛真实口碑 + 地域招聘关联
> 当前基础：24558条数据 / FastAPI / Vue3前端 / AI Agent

## 一、核心用户场景

### 场景A：查分后看能报什么学校
**优先级：P0 | 实现难度：★★☆☆☆ | 数据来源：已有**

| 项 | 内容 |
|---|------|
| 痛点 | "考了620分全省排名1万5，不知道能上什么学校，一本报考指南翻得眼花" |
| 当前状态 | 已有分数查院校接口，但交互是表单式的 |
| 改进方向 | 首页直接引导用户进入"输入分数"流程 → 自动查位次 → 推荐学校 |
| 数据 | 浙江录取数据已有，其他省需补充 |

### 场景B：深度了解一个专业
**优先级：P1 | 实现难度：★★★☆☆ | 数据来源：已有 + 新增少量**

| 项 | 内容 |
|---|------|
| 痛点 | "计算机专业到底怎么样？网上说好的说坏的都有，学校官网只写好的" |
| 解决方案 | 输入专业名称 → 一页看全：录取分趋势 + B站真实评价摘要 + 各城市薪资 |
| 数据 | 录取分已有、B站口碑已有、智联薪资已有 |
| 当前缺口 | B站评价需要做情感分析聚合，不要只展示原始帖子 |

### 场景C：两个学校做对比
**优先级：P1 | 实现难度：★★★☆☆ | 数据来源：已有**

| 项 | 内容 |
|---|------|
| 痛点 | "西安电子科大和成都电子科大，到底选哪个？分数差不多，但不知道哪个就业好" |
| 解决方案 | 并排对比两个学校的录取分、B站口碑倾向、所在城市薪资水平 |
| 数据 | 全部已有 |

### 场景D：选专业纠结
**优先级：P2 | 实现难度：★★★★☆ | 数据来源：需新增**

| 项 | 内容 |
|---|------|
| 痛点 | "不知道自己喜欢什么专业，家里人说学计算机好，但我数学不太好" |
| 解决方案 | 专业探索工具——按兴趣/学科能力/就业三个维度推荐专业 |
| 数据 | 需要新增：专业描述、课程难度、兴趣测试题等 |

### 场景E：志愿表管理
**优先级：P2 | 实现难度：★★★☆☆ | 数据来源：无**

| 项 | 内容 |
|---|------|
| 痛点 | "看了好多学校，最后忘了哪个是哪个，建了个Excel又怕填错" |
| 解决方案 | 收藏院校专业、生成"冲稳保"志愿表、导出/分享给家人 |
| 数据 | 完全靠已有数据 |

## 二、目标用户画像

### 用户A：高三考生（18岁）
- **设备**：手机，高频使用微信
- **行为**：在B站/小红书/抖音看报考攻略，信同学推荐
- **需求**：快速知道自己能上什么学校
- **决策特征**：3分钟没看懂就划走
- **对应产品策略**：**零学习成本**，打开就知道干什么

### 用户B：考生家长（40-50岁）
- **设备**：手机为主，偶尔用电脑
- **行为**：在百度/微信搜"XX大学怎么样"，看到付费咨询就想买
- **需求**：确认孩子的选择是对的
- **决策特征**：愿意花时间研究、愿意付费（几千块不心疼）
- **对应产品策略**：**信任感**——数据来源标注、有据可查

## 六、运营建议

### 6.1 种子用户获取（你独有的资源）

王洪兵律师在西安本地有优势：

1. **线下渠道**（最快）：
   - 西安本地高中 → 通过消费者协会关系进校做公益讲座《志愿填报避坑指南》
   - 讲座现场引导扫码用「驷马报考」查分数
   - 这是零成本获客，100人讲座 ≈ 30-50个用户

2. **内容营销**（可持续）：
   - 在抖音/视频号做"志愿填报法律风险"系列——律师视角解读招生简章
   - 标题示例：《招生简章里藏着这3个坑，90%家长没注意》
   - 这是你的差异化——别人讲"怎么报"，你讲"什么不能报"

3. **朋友圈裂变**：
   - 生成"我的志愿方案"分享图 → 分享给同学/家长群
   - 熟人推荐信任度高

### 6.2 产品冷启动

| 阶段 | 动作 | 目标 |
|------|------|------|
| 第1周 | 本地3所高中地推+讲座 | 200名种子用户 |
| 第2-4周 | 内容营销（法律视角） | 日增50用户 |
| 第2个月 | 用户推荐裂变 | 1000+活跃用户 |
| 高考季(6-7月) | 全力推广 | 年度峰值 |

## 七、技术路线建议

### 7.1 当前架构评估

| 层 | 当前 | 建议 | 理由 |
|----|------|------|------|
| 前端 | Vue3 CDN | 保持，不需要打包工具 | 够用，且简单 |
| 后端 | FastAPI | 保持 | 足够支撑初期1000并发 |
| 数据库 | SQLite | **过渡到 PostgreSQL** | SQLite并发写入有问题（B站+智联同时写可能冲突）|
| 部署 | 本地 | 上云服务器 | 需要公网访问 |

### 7.2 上云方案（最低成本）

```
方案：阿里云轻量服务器（¥34/月）
- 2核 2G内存 40G SSD
- Ubuntu + Docker
- 跑：PostgreSQL + FastAPI + Nginx

域名：随意（不需要备案的话用IP）
HTTPS：Let's Encrypt 免费证书
```

### 7.3 隐私与安全

考生数据是敏感信息：
- **不存用户个人信息**（姓名、电话、身份证）
- 分数和位次仅在会话中使用，不落库
- 前端不要用 localStorage 存敏感信息
- 页面底部加"数据来源声明"
