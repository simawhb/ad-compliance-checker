## 二、任务流转机制

### 2.1 开发一个新模块的标准流程

```
Step 1: [我] 读取当前阶段任务 → 明确需求
     │
     ▼
Step 2: [Codex] 出执行方案（如有需要）
     │  适用场景：
     │    - 不确定数据结构的需先策划
     │    - 反爬策略需要做方案对比
     │    - 跨多个模块的架构设计
     │
     │  不适用场景（跳过策划，直接开发）：
     │    - 明确的单个爬虫
     │    - 已有的校验/入库逻辑复用
     │
     ▼
Step 3: [我] 审核方案 → 通过后交给 Claude Code
     │
     ▼
Step 4: [Claude Code] 写代码实现
     │  用 print 模式：claude -p "任务描述" --allowedTools Read,Write,Bash
     │
     ▼
Step 5: [我] 验证结果
     │  - 代码语法检查
     │  - 如果有测试数据，跑一次测试
     │  - 确认输出格式符合规范
     │
     ▼
Step 6: ✅ 完成 / ❌ 有问题 → 回 Step 3 或 4
```

### 2.2 Codex 的使用场景

| 场景 | 频率 | 说明 |
|------|------|------|
| 执行方案策划 | 每阶段开始的总体策划 | 如"设计UGC口碑交叉验证方案" |
| 反爬策略设计 | 遇到新难点时 | 如"小红书反爬怎么做" |
| 存储架构调整 | 需求有变化时 | 如"新增招聘数据表" |
| 数据分析算法 | 需要做分析时 | 如"口碑差异指数怎么算" |

### 2.3 Claude Code 的使用场景

| 场景 | 频率 | 说明 |
|------|------|------|
| 写爬虫 | 日常 | 每个数据源一个爬虫 |

## 三、输出规范（所有代码统一）

所有 Claude Code 输出的代码必须遵循以下规范（我会在审核时检查）：

```yaml
代码规范:
  语言: Python 3.11+
  编码: UTF-8, LF 换行
  命名: snake_case, 全小写
  类型注解: 所有函数必须有类型提示
  文档: 所有函数必须有 docstring
  缩进: 4 空格
  行宽: 不超过 120 字符
  文件头: 每个 .py 文件顶部有模块说明注释
  测试: 核心函数写测试用例
  
爬虫规范:
  输出格式: JSON Lines (.jsonl)
  爬虫设置: DOWNLOAD_DELAY >= 2s
  User-Agent: 必须轮换
  重试: 每个请求重试 3 次，间隔递增
  错误处理: 解析失败不抛异常，写错误日志，继续下一条
  
数据规范:
  日期: ISO 8601 (YYYY-MM-DD)
  时间戳: YYYY-MM-DDTHH:mm:ssZ
  空值: null，不用空字符串
  小数: 分数用 NUMERIC(5,1)，金额用 NUMERIC(8,2)
  JSON字段: 用 JSONB 存储
  来源: 每条记录必须标注 data_source
```
