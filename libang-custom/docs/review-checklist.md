# 驷马合规·广告自查助手 — 审查与安全规范（2026-06-17 沉淀）

本文件记录了 2026-06-17 三轮审查的检查清单和修复模板，后续涉及代码审查、网络安全、数据隐私场景可直接调用。

---

## 一、通用代码审查清单

每次修改后自查以下项目：

### API 规范
- [ ] 返回格式统一为 `{"ok": true/false, "data": ...}` 或 `{"ok": true, **result}`
- [ ] 错误统一通过 `raise APIError("消息")` 抛出，不直接 `return {"error": ...}`
- [ ] 用户标识（openid）必填校验：`if not req.openid: raise APIError("缺少用户标识")`
- [ ] Pydantic model 中不设默认值 `"demo"` 等硬编码缺省值

### 安全基础
- [ ] SQLite 全部使用参数化查询（`?` 占位符），禁止拼接 SQL
- [ ] 前端 innerHTML 拼接用户数据/API 返回数据前，用 `e()` 函数转义 `& < >`
- [ ] 错误信息不暴露内部细节（文件路径、异常堆栈）

### 依赖
- [ ] 新增依赖需更新 `requirements.txt`

## 二、数据隐私检查清单（律师行业特殊要求）

每次涉及用户数据存储或传输时自查：

### 存储
- [ ] 用户上传的广告文案原文是否必须存储？
  - 否 → **不存**
  - 是 → **加密存储（AES-GCM），密钥放环境变量**
- [ ] 如果只存摘要，长度是否足够识别但无法还原原文？
  - 建议：20 字摘要
- [ ] 是否有数据自动过期机制？
  - 建议：30 天

### 传输
- [ ] 公网传输是否使用 HTTPS？
- [ ] AI 深度分析是否将客户文案发送到第三方 API？
  - 如是 → 必须通过用户协议明确告知

### 访问控制
- [ ] 管理后台是否有认证保护？
- [ ] 管理后台是否能看到用户全文案？
  - 建议：只展示摘要，原文脱敏
- [ ] 用户之间是否隔离？（A 用户看不到 B 用户的数据）

### 合规
- [ ] 是否有隐私协议/用户协议首次弹窗？
- [ ] 用户是否可以删除自己的数据？
- [ ] 数据删除是物理删除还是逻辑删除？

## 三、常见疏忽清单

容易漏但必须检查的点：

1. **`openid` 默认值** — CheckReq 中的 openid 必须从 `"demo"` 改为 `""`
2. **日志泄露** — 检查 uvicorn 日志级别是否记录请求体
3. **静态目录暴露** — `app.mount("/admin", StaticFiles(...))` 会导致目录下的文件无认证可访问，改用带认证的独立路由
4. **OCR 模型加载** — easyocr.Reader() 每次请求都初始化会加载几百 MB 模型，必须改为全局单例
5. **替换建议覆盖度** — 新增违规词的同时要补 `_REPLACE_MAP` 中的对应替换建议

## 四、修改验证流程

一个修改从提出到确认的流程：

1. 读 diff：`git diff HEAD --stat` 看改了什么文件
   - 如果是 bug 修复：确认修改逻辑正确
   - 如果是安全修复：确认漏洞已关闭
   - 如果是新功能：确认前后端联调
2. 检查前端适配：后端改了返回格式，前端对应位置是否同步调整
3. 检查边界情况：空输入、超长输入、并发请求
4. 输出结论："通过" 或 "未通过 + 原因"
