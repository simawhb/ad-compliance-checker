## 二、已完成的优化与修复

### 1. 密钥管理系统重构（Lucky Key 问题）

**旧问题：** 密钥 = `UPGRADE_SECRET + openid[:4]`，模式可预测，安全性差。

**新方案（已实现）：**
- `secrets.token_hex(16)` 生成 32 位随机密钥
- SHA256 哈希存储，数据库做防重用校验
- 新建 `license_keys` 表管理密钥生命周期

**新增管理 API：**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/upgrade-with-key` | POST | 用户输入密钥激活套餐 |

## 六、订阅/付费现状

**当前模式：线下密钥激活**
- 管理员通过 API 生成密钥发给客户
- 客户在系统弹窗输入密钥激活高级套餐
- 无需对接支付网关

**如果要接入在线支付（建议下一阶段）：**
1. 对接微信/支付宝支付 SDK（或使用支付平台如 PayJS、虎皮椒）
2. 支付成功后自动调用 `generate_key()` 发给用户
3. 或者支付回调直接调用 `upgrade()` 升级用户
4. 可参考 `user.py` 中的 `generate_key()` / `validate_key()` 函数

**密钥长度：** 32 位十六进制，如 `a1b2c3d4e5f67890abcdef1234567890`
